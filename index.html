Cryptography
Hybrid Email Encryption Protocol
// CSC 424 — Security Tools & Engineering
Implemented a complete end-to-end secure messaging protocol in Python combining asymmetric RSA-2048 for key exchange with AES-256-CBC for message encryption, plus SHA-256 digital signatures to guarantee both confidentiality and authenticity.
  • Sender generates a fresh 256-bit AES session key per message using os.urandom(32), encrypts the plaintext with AES-CBC, then wraps the session key using the receiver's RSA-2048 public key via OAEP/SHA-256 padding — so the session key is never sent in the clear
  • Digital signature pipeline: SHA-256 hashes the plaintext, sender signs that hash with their RSA private key using PKCS1v15; receiver re-hashes the decrypted plaintext and verifies the signature against the sender's public key, catching both tampering and impersonation
  • Manual PKCS#7 padding implementation for AES block alignment — pad bytes equal the padding length, fully reversible on decryption
  • Designed as a two-party system (sender/receiver key pairs isolated), demonstrating the complete TLS-style handshake concept at a protocol level

Multi-Method Spam Detection Engine
// CSC 424 — Security Tools & Engineering
Built a Python spam classifier applying three independent detection methods — MD5 signature hashing, live URL/SSL analysis, and unsubscribe pattern scanning — voting to classify email as spam only when at least two methods agree.
  • Signature engine: normalizes email text to uppercase, computes MD5 digest, and checks against a hash database of known spam; also applies 6 compiled regex patterns for high-signal spam phrases (lottery, urgency, pharma, phishing keywords)
  • Hyperlink analyzer: extracts all URLs via regex, flags suspicious TLDs (.tk, .ml, .ga, .xyz), detects raw IP addresses in links, and attempts a live SSL socket connection on port 443 — marking HTTP-only links and certificate failures as threat indicators
  • Unsubscribe checker: scans the full body and final 200 characters for opt-out patterns; legitimate bulk mail almost always includes these, so their absence is a spam signal
  • Voting logic: each method casts a binary spam/not-spam vote; final classification is SPAM if score ≥ 2/3, reducing both false positives and false negatives compared to single-method approaches
  • Includes a demo mode with 4 pre-built test cases (obvious spam, legit newsletter, borderline promo, phishing) with expected vs. actual output comparison

Caesar Cipher — 5 Implementations
// Cryptography Coursework
Implemented the Caesar shift cipher five distinct ways in Python — iterative, compact one-liner, list comprehension, bitwise bytearray manipulation, and alphabet indexing — to deeply explore character encoding, modular arithmetic, and Python performance trade-offs.
  • Standard iterative version: manually separates ASCII offset subtraction, modular shift, and re-encoding into discrete steps to make the math explicit; handles both upper and lowercase independently
  • Bitwise implementation: converts the entire message to a bytearray, creates a parallel shift array, and performs addition with a bitwise AND mask to clear overflow — operates on all characters simultaneously at the byte level rather than char-by-char
  • Comprehension version: single-expression encryption using a conditional list comprehension and str.join, demonstrating Pythonic style while preserving correctness
  • Index-based version: uses ascii_lowercase.index() to map characters into a 26-element alphabet array, shifting by index rather than ASCII math — a different mental model that's more readable for teaching purposes
  • Companion decrypt module uses the inverse shift (char - key) % 26, implemented symmetrically to the encrypt logic

Monoalphabetic Substitution Cipher
// Cryptography Coursework
Implemented the monoalphabetic substitution cipher two ways — a dictionary-based character mapping and a 26-character alphabet permutation string — including a general-purpose inverse key function for decryption, with a CLI driver supporting both encrypt and decrypt modes.
  • Dictionary method: key is a dict[str,str] mapping each plaintext letter to its ciphertext substitute; get_inverse_key reverses the mapping via a dict comprehension, enabling decryption with the same encrypt function
  • Permutation method: key is a 26-char uppercase string where position i gives the ciphertext letter for plaintext letter i; validation ensures the key is a true permutation (all 26 letters present, no repeats)
  • Inverse permutation algorithm: iterates the key and sets inv_key[ord(char)-65] = chr(idx+65) — constructing the reverse lookup table in O(n) without sorting
  • CLI driver validates key input interactively, rejecting non-permutation strings with an example hint, keeping the interface user-proof

One-Time Pad & XOR Encryption
// Cryptography Coursework
Built two implementations of one-time pad encryption — a single-character XOR demonstrator and a full message-level OTP — illustrating the theoretical basis of information-theoretically secure encryption and why key reuse breaks the scheme entirely.
  • Single-character version: converts two characters to their ASCII values and XORs them, producing output that demonstrates reversibility — XOR-ing the result with either original input recovers the other, the foundation of symmetric stream ciphers
  • Full OTP: iterates both message and key character-by-character, XOR-ing ASCII values and converting back via chr(); produces ciphertext that is provably unbreakable when the key is truly random, same length as the message, and never reused
  • Implementation deliberately exposes each step (msg_val, key_val, xor_val, xor_char) as named variables rather than collapsing them — designed as a teaching tool to make the XOR operation transparent

Cryptography
Vigenère Cipher Decryption
// Cryptography Coursework
Implemented Vigenère cipher decryption in Python — a polyalphabetic substitution scheme that cycles a keyword across the ciphertext, dramatically increasing resistance to frequency analysis compared to simple Caesar or monoalphabetic ciphers.
  • Key cycling via idx % keyword_length — each ciphertext character is shifted back by the corresponding keyword character's value, with the keyword repeating transparently across the full message length
  • Correctly handles mixed-case input: detects uppercase/lowercase independently, applies the appropriate ASCII offset (65 or 97), and decrypts with (cipher_val - keyword_val) % 26 to always land in the valid alphabet range
  • Non-alphabetic characters (spaces, punctuation) pass through unchanged — preserving message structure while only decrypting actual letters
  • Demonstrates why Vigenère resisted cryptanalysis for 300 years: the same plaintext letter encrypts differently depending on its position in the message, flattening frequency distributions that break Caesar and MAS ciphers

CVE-2021-3156 "Baron Samedit" Analysis
// CSC 358 — Cyber Operations
Deep-dive analysis of the heap-based buffer overflow in sudo (CVE-2021-3156) affecting all major Linux distributions. Documented the full vulnerability chain from root cause to exploitation mechanics to remediation, including evaluation of runtime mitigations.
  • Root cause: sudo failed to escape single backslashes in user arguments when MODE_SHELL or MODE_LOGIN_SHELL was active — in theory all backslashes should be doubled before this stage, but a code path allowed a lone trailing backslash, triggering a heap write-what-where condition
  • Impact: any local user (no sudo privileges required) could escalate to root on any unpatched Linux system — affected ~10 years of sudo releases before being caught by Qualys researchers in January 2021
  • Evaluated mitigations: patch to sudo 1.9.5p2, restricting sudoers access, ASLR + hardened malloc (Hardened Malloc) as runtime defenses, and RBAC implementation to contain blast radius even if exploitation succeeds
